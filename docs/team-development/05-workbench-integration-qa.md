# 成员 5：工作台分类、专注模式、集成与统一验收

## 目标

让用户在工作台明确区分多个小组和项目，并可暂时只关注一个小组；负责跨模块集成、冲突处理、回归测试和发布前检查。

## 当前代码线索

- `src/lib/dashboard.ts`
- `src/app/(app)/projects/page.tsx`
- `src/app/(app)/tasks/page.tsx`
- `src/app/(app)/app-sidebar.tsx`、`src/app/(app)/layout.tsx`
- `src/lib/project.ts`、`src/lib/reminder.ts`

## 需要完成的功能

### 1. 工作台分组

- 顶层按小组分组，小组标题显示角色、项目数和风险摘要。
- 项目卡显示小组名、项目名、任务状态分布、完成率、逾期/阻塞数量。
- 任务列表同时显示小组和项目，避免跨项目重名任务混淆。
- “全部小组”和“某小组”使用 URL 参数，例如 `/projects?team=<teamId>`；刷新和分享链接保持筛选。

### 2. 专注模式

- 提供“全部小组 / 某小组”切换，作用于统计卡、待办、动态、提醒和项目列表。
- 进入项目后保留返回前的小组筛选。
- 本期建议先用 URL 状态，后续再决定是否写入个人偏好。
- 其他小组的强提醒不消失，在顶部保留数量入口，点击后退出专注模式查看。

### 3. 集成责任

- 建立集成分支（如 `integration/student-features`），每个人继续在自己的功能分支开发。
- 负责处理 `src/db/schema.ts`、`tests/helpers.ts`、公共类型和共享样式冲突。
- 冲突时优先保留更严格的服务端权限校验。
- 给每个 PR 做 lint、TypeScript、相关测试、完整测试和构建检查。
- 检查所有新路由的登录/成员校验和所有表单的服务端 zod 校验。

## 集成验收清单

- 成员不能审核入组、管理项目、编辑他人任务或绕过依赖。
- 高/中/低优先级、截止日期、逾期、阻塞状态显示不冲突。
- 前置未完成时，网页、AI、Agent API 都不能启动/完成后置任务。
- 时间排序、未读优先、小组置顶、仅重要可以组合使用。
- 周报只使用指定小组/项目和日期范围；燃尽图没有历史事件时不伪造数据。
- 文件图标跨页面一致；邀请链接在未登录、待审、已加入、失效时正确。

## 推荐检查命令

```bash
npm run lint
npx tsc --noEmit
npm test
npm run build
```

数据库结构变化后，开发库执行 `npm run db:push`，测试库执行 `npm run db:push:test`。不要让测试连接日常开发库。

## 完成标准

完成一轮从注册、创建小组、邀请、创建项目、建任务、设置依赖、聊天、标记重要、生成周报到查看燃尽图的端到端演示，并把问题记录到 PR 或 `docs/team-development/INTEGRATION-LOG.md`。
