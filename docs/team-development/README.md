这组文档把当前需求拆成五个可以同时开始的工作流。每个人在自己的 Git 分支上开发，通过 Pull Request 合并；不要直接向 `main` 推送。

成员 5 的实现和接续步骤见[开发交接](./MEMBER5-HANDOFF.md)；跨成员缺口与手工验收见[集成验收记录](./INTEGRATION-LOG.md)。工作台功能已落地，已对接 main 中成员1的邀请/权限与成员4的消息/图标功能，完整联调仍待独立测试环境和其余功能就绪。

## 统一产品约定

### 角色

角色属于小组，同一用户可以在不同小组拥有不同角色。

- **组长**：管理成员、审核加入申请、创建和归档项目、管理迭代/里程碑、调整全组任务分工和依赖、发布正式周报、管理小组重要消息。
- **成员**：查看所属小组的项目和报告；创建任务或编辑自己负责的任务；更新自己负责任务的状态、完成说明和进度；上传文件；参与聊天；使用个人筛选。
- 成员不能修改其他人的任务负责人、强制完成被前置任务阻塞的任务、审核加入申请、删除全组重要资料。
- `teacher` 是历史角色。学生端本期不扩展老师功能；新页面使用“组长 / 成员”语义，是否将历史 `teacher` 映射为只读成员由成员 1 记录处理方案。

### 任务语义

- `status` 是执行状态：待办、进行中、已完成。
- `priority` 是紧急程度：高、中、低。
- `blocked` 是被前置任务阻塞，不代替 `todo`/`doing`。
- 后置任务只有在全部前置任务为 `done` 后才允许进入 `doing` 或 `done`；服务端、网页、AI 工具和 Agent API 使用同一校验。

### 消息排序语义

用户可以在消息中心设置：

1. **按时间排序**：微信式默认行为，按最近活动时间倒序；未读不自动移动到顶部。
2. **未读优先**：有未读消息的会话/通知排在已读之前，同一组内按最近活动倒序。
3. **小组置顶**：个人设置中将一个或多个项目群聊置于普通会话之前，不改变其他成员的视图。

最终排序键为 `pinned DESC` →（未读模式时）`hasUnread DESC` → `lastActivityAt DESC`。按时间模式时跳过未读键。

### 工作台筛选语义

选择某个小组后，项目卡片、统计卡、我的待办、最近动态、提醒数量都只统计该小组。选择“全部小组”才汇总全部范围。筛选状态写入 URL，刷新页面仍然保留。

## 并行开发规则

1. 每个人优先修改自己文档列出的主目录；跨目录改动在 PR 描述说明。
2. 共享 schema 时，在 PR 描述列出新增表/字段/枚举和索引，由集成者处理冲突。
3. 所有服务端函数必须有权限校验；页面隐藏按钮不能代替服务端权限。
4. 每个 PR 写清功能、数据库变更、测试命令、已知限制、截图或接口示例。
5. 合并前通过 `npm run lint`、`npx tsc --noEmit` 和相关测试；合并者再跑完整 `npm test`。
6. schema 冲突时保留双方字段，检查 `onDelete`、索引、唯一约束和测试清理脚本；不要用 `git reset --hard`。

## 建议合并顺序

五个人可以同时开发。合并时建议先合并成员 1 的权限基础，再合并成员 3 的任务约束、成员 2 的报告/迭代、成员 4 的消息/资产，最后由成员 5 完成工作台整合和全量验收。这只是合并顺序，不是开始顺序。
