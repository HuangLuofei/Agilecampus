## 独立数据库验证

先创建独立 PostgreSQL 数据库，例如 `agilecampus_test`，在不提交的 `.env.test` 配置连接。库名须以 `_test` 结尾，且不能与 `.env` 开发库同名。

确认连接目标后执行 `npm run db:push:test` 初始化测试结构，再运行 `npm test -- tests/workbench.test.ts`，最后完整 `npm test`。测试会清理该独立库，不得指向日常开发或生产数据。

7项回归覆盖多组重名、空组、未加入组、退组残留指派、多负责人、状态/逾期/阻塞计数、超过40任务时待办排序、成员/组长提醒范围与去重。

## 手工验收

准备甲组（当前用户为组长）、乙组（当前用户为成员）、空组、未加入组，并设置同名项目/任务及不同负责人、优先级和截止时间。

| 操作 | 预期 |
|---|---|
| 打开工作台 | 显示所有所属组及空组，任务与动态注明组/项目 |
| 专注甲组并刷新 | 统计、项目、待办、动态、提醒、侧栏都按甲组展示 |
| 专注空组 | 零统计和空列表，不回退其他组 |
| 点击统计、任务状态、资产搜索/清除 | 保留当前小组 |
| 切换资产小组后新增 | 只能选择当前组项目，保留上传、删除和文件图标 |
| 从待办进入看板，操作文档/时间线/资产再返回 | team 和任务深链按适用页面保留 |
| 只有一个提醒项目 / 多个提醒项目 | 分别直达看板 / 工作台提醒列表 |
| 当前组无到期任务，其他组有强提醒 | 不展示其他组明细，只保留强提醒数量入口 |
| 创建/编辑/拖拽/删除到期任务 | 成功后共享提醒及工作台刷新；失败不刷新 |
| 非法/未加入/已退出组的 team URL | 拒绝数据访问 |
| 两个前置依次完成 | 阻塞任务只计一次，全部完成后解除；强制执行由成员3验收 |
